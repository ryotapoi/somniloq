第1段階で確定した受け入れ契約。TOML 設定・複数入力、Codex の本人／明示直接親と原文モデル、Claude Code の子孫本人／厳密な直接親と path root 所属の保存、各本人 REF の発行と選択、専用 migrate は実装済み。共通 resolver によるまとまり・確定子孫の解決は実装済み。複数 REF・確定子孫 show の原文 TSV/JSON envelope、発言フィルタ・ページ・一行表示・旧入口統合は実装済み。共通 regexp 照合器と `search --session REF` の全一致詳細は実装済み。session 指定なしのまとまり一覧・総数・ページは実装済み。input/source/project は一覧・詳細で候補本人を先に選び、共通 regexp で照合する。活動日4 mode、日付/zone付き RFC3339 と dayBoundary、imported-since は実装済み。表示日時・整列は全 group の本人原文日時を使う。現在利用できる CLI の動作は [scope](../rules/scope.md) が正本。本書は v0.14.0 第2〜6段階に適用し、実使用と最終確認は第7段階に残す。[元ログと fixture](v0.14.0-log-evidence.md)、[移行契約](v0.14.0-migration.md) は本書と合わせて読む。現行 usage・README・skill は実装時に同期する。まとまり一覧の試用と取得コーパスの実測は[検索計測](v0.14.0-search-measurements.md)を参照する。

## 設定

全 DB 操作（import、migrate、search、show）で `--config NAME_OR_PATH` を必須とする。help、version、config init には不要。`--db` は廃止する。未指定・欠落時は exit 2、stderr に `Run somniloq config init, then use --config default.` と不足項目を表示し、DB を開かず自動生成もしない。

`config init [NAME] [--output PATH] [--db PATH]` は NAME 省略時 default。NAME は `[A-Za-z0-9_-]+`。`--output` 省略時 `~/.somniloq/config/NAME.toml`、`--db` 省略時 `~/.somniloq/NAME.db`。init は設定だけを作成し DB は作成しない。parent directory は作成するが、設定は排他的作成で symlink を含む既存宛先を拒否する（exit 2）。任意出力でも NAME が既定 DB を決める。stdout は作成した設定の絶対 path 一行。

`--config` が NAME 規則を満たす場合は設定名。それ以外は path とし、相対 path は実行 cwd 基準。`foo.toml` は path、名前 foo は `--config foo`、拡張子なし相対ファイルは `./foo` と指定する。

全キーは以下だけ。未知キー・型違い・空 db・空 inputs・空 root・未知 source・不正 dayBoundary を拒否する。旧 JSON を自動変換・探索しない。旧 projectAliases は手動で projectAliases に転記できる。旧 excludeUserMessagePatterns は原文取得の除外を廃止するため受理しない。dayBoundary は引き継げる。

```toml
db = "~/.somniloq/default.db"
dayBoundary = "00:00"

[projectAliases]
example = ["old-example"]

[[inputs]]
name = "Claude"
source = "claude-code"
root = "~/.claude/projects"

[[inputs]]
name = "Codex"
source = "codex"
root = "~/.codex/sessions"

[[inputs]]
name = "Cursor"
source = "cursor-agent"
root = "~/.cursor/projects"
```

init はこの3入力を生成する。dayBoundary と projectAliases は任意（既定 `00:00` と空）。inputs.name は任意の表示用文字列で DB に保存しない。source の入力値は上の CLI 表記のみ、DB/JSON/REF は `claude_code|codex|cursor_agent`。表示名の重複は許す。alias のcanonicalと別groupのaliasが重なる設定は拒否し、順序で勝者を決めない。

設定自体の symlink を実体解決後、その親を相対 db/root の基準とする。path は `~` または `~/` の先頭だけを現在 user の home へ展開（`~other`、環境変数展開なし）、相対解決→絶対化→Clean→既存 symlink の実体解決。DB が未作成なら存在する最長 parent を実体解決して末尾を接続する。欠落 input root も同じ方法でキーを決め、import では未使用として0件とする。root が後着してsymlinkに変わった場合は実体キーが変わるため別入力。path の大文字小文字は変換しない。

通常取り込みの入口は `import --config NAME_OR_PATH [--input PATH...] [--source all|claude-code|codex|cursor-agent] [--full] [--yes]`。未指定では設定の全入力、input/sourceは交差条件とする。fullは選択入力の会話・差分状態を再構築し、別入力は保持する。既存の確認プロンプト/yes/非対話規則を引き継ぐ。通常importのunparsed診断・部分成功は現行規則、履歴の安全な旧行置換は専用migrateだけが担う。search/showはDB未存在・非対応revisionでは書込みせず拒否する。

## 入力・会話・REF

入力キーは `sha256(UTF8(DB source) + NUL + UTF8(canonical root))` の64桁小文字hex。DB 内では短い整数 FK で入力を参照する。同じ source と実体 root の重複設定は一入力として一回走査する。root 移動は別入力、name変更は同入力。本文の類似による統合はしない。

source 固有 identity は空白なし JSON 配列の UTF8（JSON string escaping を用い HTML escape なし）。Codex/Cursor は `[sessionId]`、Claude root は `[sessionId]`、Claude 子・孫は `[rootSessionId,agentId]`。Claude は一つの root 内の agentId を使うため root と同じ sessionId を持つ子を潰さない。同じ identity を別入力では統合しない。

REF は `slq1:INPUT_KEY:SOURCE:BASE64URL_IDENTITY`。Base64 は padding なし RFC4648 URL alphabet。path・name・DB rowid をREFに露出しない。完全 REF のみ受理し、短縮・裸IDは受理しない（曖昧選択を防ぐ）。同入力の再処理・別DBで同じrootから構築した場合に安定する。root移動・identity変更でREFは変わる。未知入力の旧保存値は [legacy REF](v0.14.0-migration.md) を使い、通常REFと混同しない。存在しないREFはexit 2。

## 原文・順序・日時

原文単位は source の一つの user/assistant record にある text block。Claude user string はそのまま、配列text、Codex input_text/output_text/text、Cursor text を配列順に `\n\n` で連結する。内部改行・空白・tag を保持し、trim は空白だけの本文か判定するためだけに使う。空白だけの本文・tool-only・非本文recordには番号を与えない。block境界も保存する（block textsの配列）ため連結前を復元できる。tool全文を原文と呼ばない。sidechain 本人の本文は除外しない。

本人の原文発言に会話内1始まり `messageNumber` を与える。物理行順で、日時順に並べ替えない。Codex 明示継承境界の未満は context として区別し本文・採番・活動日時・検索に含めない。最初の有効metadataで本人を固定、後の親metadataでは変更しない。境界がない旧形式は類似文や最初のuserを根拠に除外しない。境界ありでordinal欠落の本文は所属不明として診断し、本文の推測分類はしない（移行は失敗）。正常 import の診断/再処理は既存末尾行契約を引き継ぐ。

Codex同本人の複数rolloutは入力内相対pathのUTF8 byte辞書順→物理行。payload.idがある本文は同一ID・同一role/block/timestampで重複除外し、同一ID内容不一致は競合。IDのない本文は出自ごと保持。新規の前方path・途中編集・辞書順で前方にあるrolloutへの追記で既存本文の前に新本文が挿入される場合は、本人全体を再構築してcanonical原文列の位置で再採番する。既存番号を維持できるのは、既存canonical原文列が不変、または新本文がその列末尾だけに追加される場合（単一rolloutの末尾追記・最後方rolloutの追記・その差分再開）に限る。同じファイル集合でも前方rolloutへの追記はこの条件を満たさない。差分importも全文再処理も同じ最終ファイル集合から同じ順序・番号を返し、取り込んだ時刻の順にはしない。番号は永続UUIDの代替ではなくこの原文列の位置。[前方追記fixture](../../internal/ingest/testdata/v0.14.0/README.md#複数-rollout-の前方追記) がこの境界を示す。

発言日時はそのrecord自身のtimestampだけを保存し、metadata、mtime、取り込み時刻から埋めない。元のRFC3339文字列も保存し比較にはUTC instantを使う。不正・空・欠落は未知としてraw値は残す。会話metadataの開始日時は原文活動日時の代替にしない。legacy保存時刻の由来は未知。importedAt は成功トランザクションで新規保存/更新した会話ごとに実行開始で一度取得した時刻を共有し、不変skipは更新しない。

## 関係とまとまり

Codexは明示thread_spawn.parent_thread_id、Claudeは同一親ファイル内の Agent（旧名Taskも受理）call id→tool_result.tool_use_id→構造化toolUseResult.agentId→子agentId の全リンク一致だけで直接親を確定する。本文中のID、parentUuid、時刻・類似本文は根拠にしない。Claude root 所属は path から別に保存する。未知の直接親でもroot所属が分かる子は所属rootのまとまりへ含めるが、直接子と表示しない。

関係キーは同じ入力内のみ。親未取込でも参照キーを保存し、後着時に接続する。Codex欠落親は明示親鎖の最上位keyをまとまりkeyとし、member REFの最小辞書順を一覧refにする。親が後着したら一覧refはroot本人REFとなる。個別REFは変えない。関係が未知でrootもない会話は単独。競合/循環の辺は未確定として診断し、確定辺だけを使う。親欠落placeholderを本文を持つ会話として数えない。

`search --session REF` は**本人と直接親が確定した子孫**だけ。祖先・兄弟やroot所属だけの子を暗黙に含めない。子の作業を探す指定の局所性を優先する。root全体が必要なら一覧の `members` から複数REFを `show` に渡す。`show --descendants` も同じ確定子孫を展開する。root所属が分かるが直接親未知の子も一覧のmembersには出る。この選択を第7段階で試用する。

## 検索と日時

`search [PATTERN] [-e PATTERN...] [-F] [--all] [--session REF] [--input PATH...] [--source SOURCE...] [--project TEXT] [--since VALUE] [--until VALUE] [--time-mode active|started|last|overlap] [--day-boundary HH:MM] [--imported-since RFC3339] [--limit N] [--offset N] [--format tsv|json]`。

位置PATTERNと-eは共存でき全てpattern列へ追加する。通常OR、--allで各patternが探索範囲に一回以上あるAND。--sessionなしではpattern省略で一覧、ありではpattern必須。空文字patternは拒否（exit 2）、有効な `^` 等のゼロ幅は受理する。Go regexpの大小文字区別が既定、`(?i)`を許す、lookaround/backreferenceは無効。-Fは全patternへQuoteMetaを適用。無効patternはDB query前に拒否する。

先に input/source/project/imported-since で候補会話を選ぶ。sourceはCLI表記3種のみ（searchではallを受理しない）。複数input/sourceは各OR、異なる条件種はAND。inputは設定基準pathと同じ正規化で入力キー照合。projectはrepo_pathの末尾名の大小文字区別substring、alias完全一致時だけcanonicalとaliasesへOR展開する。project未知は一致しない。取り込み日時は候補会話のimportedAtが下限以上か判定。この候補だけの本文を照合し、保存関係で同じまとまりへ集約する。表示members・開始/最後はフィルタで消えない元のまとまり全体、`matchedMembers` は候補に残ったmember。従って子だけprojectに一致してもまとまり一覧一件だが、除外された親の本文でANDを満たさない。

開始/最後はまとまり全体の本人原文の既知日時の最小/最大（最後は完了時刻ではない）。since以上・until未満の半開区間。日付値は現在ローカルzoneのdayBoundaryから翌日の同境界まで、日時値はtimezone必須RFC3339。日付untilは翌日境界へ進め、その日を含む。既定time-modeはactive、期間なしでmode指定はエラー。started/lastは集約開始/最後が区間内、overlapは `last >= since && start < until`（未指定側は無限）。activeは候補内の期間内実発言だけを本文照合に使い、patternなしでも一件以上必要。他modeは期間でまとまりを選び候補の全文を照合する。ANDもこの同じ対象本文集合で判定し、未知日時はactive対象外。日時条件なしでは未知本文を落とさない。

詳細は期間内実発言検索を維持し、--time-mode は active のみ受理する。他 mode は一覧専用として exit 2 で拒否する。明示 active も期間指定を必要とする。imported-since は一覧と同じ個別候補条件を適用する。

詳細では同じ照合器の `FindAllStringIndex` のUTF8 byte `[start,end)` を返す。patternごとの重ならない全一致を収集し、同一区間は一箇所に統合してpatternIndexes（1始まり）を残す。異なるpatternによる重なった区間は別箇所。ゼロ幅/隣接空一致はGo APIの結果どおり。AND不成立は詳細0件、成立時は全patternの一致を出す。各member原文番号順、各発言でstart→end順に `occurrenceNumber` を1から採番する。前後は一致の先頭/末尾を含む行を丸ごと返す `lineText`（ゼロ幅も該当行、末尾は末尾行）。matchTextも保持し、位置は全文基準。サロゲート/character offsetへ変換しない。LF は直前の行に属し、非空一致の末尾行は end-1 の行とする。ゼロ幅は start の行、末尾 LF の後の本文末尾は空行。lineText は行末 LF を除き、複数行の途中 LF は保持する。

## show

`show REF... [--descendants] [--role user|assistant] [--messages A:B] [--since VALUE] [--until VALUE] [--day-boundary HH:MM] [--limit N] [--offset N] [--tail N] [--one-line] [--format tsv|json]`。

REFは最低一つ、全REFを先に検証して一件不正でも出力しない。入力REF順に選択、descendantsは親先行DFS・兄弟REF辞書順で展開し、最初に現れた会話だけを残す。既知root所属だけで親未知の子は展開しない。会話ごと原文番号順に連結→role/番号/日時filter→ページ化→one-line。messagesは両端含む正整数、`A:`/`:B`可、空両端・逆順はエラー。複数会話に同じ番号条件をそれぞれ適用する。日時はactive実発言のみ、未知は日付filterに含めない。

既定全文（limit=null、offset=0）。limitは非負整数、0は0件。offsetは非負。tail Nはフィルタ後の全列末尾N件を元の順序で返し、limit/offset明示と併用不可。先頭はlimit N。複数会話でもpage単位は発言で、会話をまたぐ。one-lineは最初のLF以前だけ（CRLFのCRも除く）、フィルタや一致判定を短縮本文でしない。旧outline/summary/turn/表示除外は提供せず同じfilter/one-lineへ統合する。

## 出力

既定TSV、JSONはUTF8 object。各入口で同じenvelope `{items,total,count,limit,offset,hasMore,nextOffset}` を使う。totalはfilter後page前、countはitems数、limitは無制限null、nextOffsetは続きがあればoffset+count、なければnull。limit=0ではhasMoreはoffset<total、nextOffset=null（進まないpageを自動反復しない）。末尾超過もtotalを返す。件数とitemsは同じread transactionで取得する。

一覧既定limit=20、last既知の降順→未知は最後→まとまりkey辞書順。詳細/showは既定無制限。詳細は会話REF辞書順→番号→箇所。showは前節の入力順。表示日時は既知raw値、不正rawはそのまま、未知null。復元不能のlegacy blocksはnull、既知の配列は空でも `[]`、booleanとintegerは型を保つ。JSONは以下の全fieldを常に持ち追加で省略しない。

| item | fields |
| --- | --- |
| 一覧 | ref, input（canonical rootまたはnull）, source, project（root値またはnull）, title（root値またはnull）, startedAt, lastAt, importedAt（membersの最大）, members（REF配列）, matchedMembers（REF配列）, memberCount |
| 一致箇所 | ref, messageNumber, occurrenceNumber, role, timestamp, startByte, endByte, patternIndexes, matchText, lineText |
| show発言 | ref, messageNumber, role, timestamp, text, blocks（連結前text配列）, parentRef（確定し存在する親またはnull）, rootRef（所属rootが存在する場合のREFまたはnull）, provenance（source_record または legacy_saved） |

一覧project/titleは存在するrootの値のみ、子から推測しない。欠落rootではnull。TSVは先頭 `# page\t` の後に同envelopeのitemsを除くcompact JSON、一行header、その後itemごと一行。列順は上表field順。nullは `\N`、配列はcompact JSON、文字列はbackslash→`\\`、tab→`\t`、LF→`\n`、CR→`\r` の順にescapeして可逆にする。JSON一行textもtextだけ短縮、blocksは原文のまま。JSON/TSVは本文抜粋を一覧に載せない。

成功は0（0件含む）、入力/設定/REF/通常コマンドの非対応DBは2（migrateのdigest/receipt/既存移行先拒否は1）、I/O・保存・部分import/migrate失敗は1。stderr診断、stdoutは機械可読出力だけ（migrateのcopy確定後の部分失敗summaryも出す）。importのsummary/unparsed診断は現行仕様を引き継ぎ、migrateのsummaryは移行契約に従う。表示用現在時刻を日時unknownに代入しない。

## 代表利用例

ここは実装予定の例であり現行バイナリの試用結果ではない。`R` と `C` は fixture expected.json のroot/child REF（実際は完全REF）。[fixture対応表](v0.14.0-log-evidence.md) をオラクルとして第6段階でCLIへ通す。

単語から作業へ戻る: `somniloq search --config default -F "Inherited question" --format json` で親のInherited questionがあるまとまり一件を取得し、`search --config default --session R -e "Inherited question" -e "Child answer" --all --format json` は親Inherited questionと子Child answerの両箇所を返す。子REF Cに同じANDを渡すと祖先Inherited questionが範囲外なので0件。`show --config default C --messages 1:1 --format json` は本人先頭assistantのChild answerを元番号1で返す。

指定日の材料: `search --config default --since 2026-10-01 --until 2026-10-01 --time-mode active --format json` からmembersを選び、一回のshell呼出しで渡す。

```sh
refs=$(somniloq search --config default --since 2026-10-01 --until 2026-10-01 --format json | jq -r '.items[].members[]' | sort -u)
if [ -n "$refs" ]; then
  printf '%s\n' "$refs" | xargs somniloq show --config default --since 2026-10-01 --until 2026-10-01 --format json
fi
```

REFは空白を含まない。この例のsort順がshowの会話順となる。日時不明Cursorはこの日の候補/発言に入らないが期間なしshowは本文を返す。日時絞り込みで期間を跨ぐ会話の実発言だけを返し、開始日の一致で全文を渡さない。

JSON成功の形（空ページ例）:

```json
{"items":[],"total":1,"count":0,"limit":20,"offset":20,"hasMore":false,"nextOffset":null}
```

TSV成功の同じページ:

```text
# page\t{"total":1,"count":0,"limit":20,"offset":20,"hasMore":false,"nextOffset":null}
ref\tinput\tsource\tproject\ttitle\tstartedAt\tlastAt\timportedAt\tmembers\tmatchedMembers\tmemberCount
```

`search --config default '(?=foo)'` はexit2、stderr `invalid pattern 1: unsupported regexp syntax`、stdout空。`show --config default bare-id` はexit2、stderr `invalid REF: expected slq1 full reference`。`search` はexit2、設定作成案内。成功0件は上のenvelopeでtotal=0、offset=0、hasMore=false。結果のtotalは一覧のまとまり数、詳細の箇所数、showの発言数で混同しない。
