# 技術的制約・禁止事項

- 後方互換性のためだけの shim / deprecated / fallback 分岐を追加しない
- `--no-verify` でフックをスキップしない
- 明示的な指示なしに force push しない

## SQL とデータの意味

- JSONL 由来の値は SQL プレースホルダ経由で扱い、文字列連結で SQL を組み立てない
- 文字列カラムの `MAX()` で「最新」「代表」を選ばない。例外は固定幅に正規化された RFC3339 UTC のタイムスタンプ列（辞書順 = 時刻順が成立する）だけで、それ以外の TEXT カラムでは辞書順比較になり意味が壊れる。レビューポイント: `MAX(<TEXT カラム>)` を含む SQL 変更では対象カラムの順序の意味を確認する
- 集約クエリで GROUP BY キーと表示値に別々の短縮・変換を適用しない（情報が縮退して一覧に同名行が並ぶ）。レビューポイント: 集約の変更では GROUP BY キーと出力列の変換が一致しているか確認する
- 本人原文の発言番号は source の物理順から決め、timestamp や SQLite rowid から再採番しない。Codex の同本人に属する複数 rollout は入力内相対 path の UTF-8 byte 辞書順、次に物理行順で canonical 列を作る。前方への追記・途中編集などで列が変わる場合は、本人の本文・文脈・関係と対象 cursor を一つの transaction で再構築する。失敗時に既存の本人と cursor を部分更新しない。レビューポイント: message 書き込み・削除や差分判定を変える際は、通常差分と full が同じファイル集合から同じ番号を返すか確認する

## 取り込みと保存済みデータ

- import のフィルタ・スキップ・バリデーションを変更したら、既存 DB に保存済みのデータとの食い違いを確認する（新規取り込み分と過去データで内容が変わる。`--full` 再取り込みの案内が必要かも含めて判断する）
- 取り込み日時などの「現在時刻」は処理単位で 1 回取得して共有する。レコード処理ループの中で都度取得しない（`internal/core/import.go` のテスト差し替え可能な `timeNow` を使う）

## CLI 表面

- フラグ・サブコマンド・モードを追加・変更したら、`cmd/somniloq` の usage 定数・ヘルプ文字列に同じコミットで反映する（CLI 仕様の正本 `docs/rules/scope.md` と README の同期は scope.md 冒頭の規定に従う）
