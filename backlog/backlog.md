# Backlog

## 運用ルール

- Backlog には、今後着手でき、完了を判定できる作業を `- [ ]` 形式のタスクとして置く。
- 対応要否を決める調査もタスクにできる。観察事実だけを残さず、判断したい問いと、判断をもって完了とすることを明示する。
- 粗いメモで起票してよいが、着手前に目的と受け入れ条件を読める粒度へ詰める。
- タスクの行には短い作業名を書き、説明は空行を挟んだ字下げ段落に分ける。
- バージョン番号を付ける場合は SemVer に従う。
- タスクは `###` 見出しでグループに分ける。バージョンが確定したグループだけ、`### v0.11.0 名前` のように見出しへ番号を付ける。
- グループが大きい場合は、`####` 見出しでさらに分割してよい。

## タスク

### セッションのまとまりを軸にした検索・閲覧の再設計

対象版は未定。過去の作業を単語から見つけることと、指定日の Daily Note に使う原文を取り出すことを先に成立させる。以下は未着手の変更タスクであり、現行仕様を置き換えた記述ではない。

- [ ] 検索・閲覧の出力契約と正規表現の範囲を確定する

  初回 `search` は親と関係が分かる子・孫を1行にしたセッション一覧のみ、`search --session REF` は指定したまとまり内の全一致箇所、`show` は原文と定める。正規表現を通常とし、複数 `-e` は OR、`-F` は文字どおり、まとまり全体の AND は専用指定（仮 `--all`）とする。対応構文・大小文字・Unicode・無効式・空一致、同一発言内の全一致の位置と重複規則を仕様に固定し、rg 完全互換を無条件に約束しない。LLM による要約は生成しない。

- [ ] 代表的な元ログで親子・孫の復元条件を確認する

  Claude Code は子が root と session ID を共有する例から独立した子の参照名・所属 root・直接の親を識別し、meta と tool call から孫までたどれるかを確かめる。Codex は元ログにある親 ID が現在保存されていない経路を確認する。Cursor Agent の日時・場所・親子が不明な記録は推測せず、親の欠落、後からの親取り込み、引き継いだ文脈と本人の発言の重複も代表例で判定する。

- [ ] 原文と関係の手がかりを保存できる形式へ見直す

  確定した出力から必要な保存形式を決め直し、親・子・孫の独立した参照名、所属 root、直接の親、順番と分かる日時、人と AI の原文、関係復元に必要なメタデータを保持する。既存 DB・再取り込み・欠落した親の後着に対する扱いを決め、別起動の会話を文面や近い時刻だけで結びつけない。

- [ ] 一覧と詳細で同じ検索判定を使えるようにする

  modernc SQLite の Go 関数登録を利用し、bind した pattern を共通の照合器で判定する。候補条件で絞る → 本文を照合する → 親子のまとまりに集約する → 総数を数える → 並べる → ページ化する順序を守り、件数制限後に正規表現を掛けない。親の `foo` と子の `bar` でも同じまとまりの AND を満たし、SQL の一覧判定と詳細の一致箇所がずれないことを確認する。任意の正規表現では候補本文の全走査が起こり得るため、実データで時間を測る。

- [ ] セッション一覧としての `search` を実装する

  語の省略、project と alias、source、`active` / `started` / `last` / `overlap` の日付条件、範囲、dayBoundary、活動日時と区別した `--imported-since` を扱う。`active` は期間内の原文発言で語を判定し、他の3条件はまとまりの開始・最後の記録・期間で選んで本文全体を探す。最後の記録を完了時刻とみなさない。日付だけの `--until` は指定日全体を含み、日時指定の `--until` は排他とする。初回出力に本文抜粋を混ぜず、全 filter 後・ページ化前のまとまり総数、今回の件数、`--limit` / `--offset`、続きの有無と次位置を TSV・JSON で返す。0件・末尾超過でも総数を返し、一度の検索内で件数と項目を一致させる。

- [ ] 選んだセッション内の全一致箇所を返す

  `search --session REF` は検索パターンを必須とし、関係が分かる子孫まで同じ照合器で探し、代表1箇所へ縮めず、10箇所なら10箇所を返す。実際に一致した会話の参照名・発言番号・同一発言内の箇所番号と前後の原文を示す。制限の指定がない場合は全件、明示した場合だけ箇所単位で分割し、詳細の `total` はセッション数でなく一致箇所数だと明示する。

- [ ] `show` で選んだ原文を必要な単位で取得する

  本人の全文を既定とし、先頭 N 件・末尾 N 件・発言番号範囲・指定日の発言を選べるようにする。子だけの参照、親と子孫を別々の本文として含める指定、複数参照名の一括取得、各出力の JSON を提供する。従来の `--turn` / `--tail` / `--summary` や `outline` と表示除外設定はこの整理だけで廃止しない。

- [ ] 公開 CLI と正本・派生文書を同期する

  独立した `sessions` を `search` の一覧へ統合し、横断検索の抜粋は対象セッション指定後に見る形へ変更する。期間だけで複数全文を直接出す入口は、`search` で参照名を選び `show` に複数渡す形へ移す。一括取得能力を保ちながら、変更する CLI・JSON の利用者向け案内、`docs/rules/scope.md`・該当 `docs/specs/`・README 両言語・skill を同期し、既存利用側の移行手順を示す。

- [ ] 次期版と旧 DB の扱いを決める

  v0.13.0 で専用 `backfill` は廃止済み。新しい出力と保存形式に合わせ、0.x での再リリースを含めて対象版と旧データの扱いを決め、必要なタスクの重複・順序を整理する。

- [ ] 二つの利用場面と境界条件を fixture で検証する

  単語から過去作業のまとまりを選んで原文へ戻る経路と、指定日の実発言だけを Daily Note へ渡す経路を通す。0件・末尾超過ページ・親子をまたぐ AND・SQL と詳細の同一判定・同一発言内の複数箇所・日時や親が不明な例を含め、総数、参照名、元の発言、JSON が一致することを検証する。
