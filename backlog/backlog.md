# Backlog

## タスク

### v0.14.1

- [ ] **移行の性能評価条件を定め、改善前後を比較する。** コピー、ログ走査・解析、所属証拠の集約、会話の置換を分けて計測し、各改善の効果を判断できる基準を作る。
  - 合成入力で総 bytes、ファイル数、会話数、最大会話サイズ、異なる cwd 数を変え、経過時間・ピークメモリ・走査回数・Git 起動回数・旧行照合の SQL 回数を確認する。初回と同一 snapshot での再実行を区別する。
  - 実行前に時間・メモリ・ディスク使用量の上限と中止条件を決め、小規模から段階的に測る。利用中の `~/.somniloq` や実ログを性能試験の作業領域にしない。
  - 以下の改善後に同じ条件で比較し、入力規模に対する増加傾向と残る制約を確認する。所要時間だけでなく、既存の移行 fixture に基づく保存結果・失敗時保持・再実行の保証も確認する。

- [ ] **Codex メタデータからの Git 呼び出しを削減する。** 同じ cwd のリポジトリ判定を処理内で再利用し、所属検証や採用しない埋め込みメタデータに不要なリポジトリ判定を行わない。
  - 入口は `internal/ingest/codex/jsonl.go` の `parseSessionMeta` と `internal/core/repo_path.go` の `ResolveRepoPath`。結果の再利用期間と失敗時の扱いを定め、別の CLI 実行に古い判定を持ち越さない。
  - 採用しないメタデータも構文・ID・親の検証と診断は維持する。通常 repository・worktree・submodule・非 Git cwd の保存値と、Git 環境変数を除外する既存動作を保ち、同じ cwd の大量ログで Git 起動数がメタデータ件数に比例しなくなることを確認する。
  - JSON 解析の改善とは独立して進められる。共有する通常 import のリポジトリ判定にも回帰がないことを確認する。

- [ ] **移行時の JSONL 重複解析をなくす。** `internal/ingest/codex/group.go` の strict 検証と `adapter.go` の保存用処理で、同じ物理行・メタデータを解析し直さず結果を共有する。
  - 所属検証をメタデータ適用前に行う順序、埋め込み親・本人境界・ordinal・payload ID の判定、物理行番号、本文と block 境界を維持する。
  - 移行時の厳密な拒否と通常 import の部分取り込みを混同せず、不正 JSON・未完末尾・所有者不明の診断と cursor の扱いを維持する。
  - 大きい行や本文以外の record を含む合成入力で CPU 時間と allocation を比較する。Git 呼び出しの削減効果と区別して評価する。

- [ ] **移行時のメモリ保持と旧行照合を入力全体の本文量から切り離す。** `Migrate` / `buildGroups` が全入力の生 bytes・解析済み本文・全物理行の証拠を一括保持する構造を見直す。
  - 全入力の所属・競合を確定する段階と、会話単位の本文読み込み・置換を分ける。完了した会話の本文を解放し、証拠・診断の保持量と単一の巨大会話も含めてメモリ上限を評価する。
  - 旧 Codex 行と照合する証拠・候補を必要範囲に絞り、旧 DB に存在しない全物理行 UUID への SQL 照会を避ける。失敗した group、継承文脈、重複排除された物理行も所属判定の証拠として扱い、全入力の確認前に旧行を削除しない。
  - 本人本文・旧行削除・cursor の原子的な確定、所属不明行と他 source の保持、同一 snapshot の再実行を維持する。共有 builder を変更する場合は、通常 import の差分 skip・診断・full の結果も確認する。
  - 最大会話サイズを固定して総入力を増やし、全入力の生 bytes・本文の同時保持がなくなることを確認する。次の snapshot 確認方式と整合させる。

- [ ] **会話ごとの入力ディレクトリ全走査を削減する。** `internal/core/migrate.go` の `checkMigrationSnapshot` が置換前と commit 前に行う全走査・ファイル集合のコピーと sort を見直す。
  - 入力全体のファイル集合と対象会話の内容確認を分け、全走査が会話数に比例して繰り返されない方式を決める。対象本文の再読込は会話内ファイルに限られるため、全走査の費用と分けて評価する。
  - 入力のファイル集合の追加・削除・rename、対象内容の変更、走査失敗を置換前と commit 前の確認で検出し、不完全な会話で旧履歴を置換しない。確認を起動時の一回だけに減らす案や size/mtime だけで同一内容とみなす案で保証を弱めない。
  - 再実行時に保存済み発言の rollout（body/context を含む）が欠けていれば、既存本文・旧行・cursor を保持する。変更検出の保証と確認タイミングを先に定め、方式が確定してから実装する。確認時点間を含む filesystem 全体の原子的 snapshot までは保証しない現契約と区別する。
  - メモリ保持の改善と共通のファイル情報を使う範囲を揃え、固定サイズの会話を増やした場合の走査費用と、置換中の変更・失敗時の保存結果を確認する。
