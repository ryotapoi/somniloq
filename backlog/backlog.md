# Backlog

## 運用ルール

- Backlog には、今後着手でき、完了を判定できる作業を `- [ ]` 形式のタスクとして置く。
- 対応要否を決める調査もタスクにできる。観察事実だけを残さず、判断したい問いと、判断をもって完了とすることを明示する。
- 粗いメモで起票してよいが、着手前に目的と受け入れ条件を読める粒度へ詰める。
- タスクの行には短い作業名を書き、説明は空行を挟んだ字下げ段落に分ける。
- バージョン番号を付ける場合は SemVer に従う。
- タスクは `###` 見出しでグループに分ける。バージョンが確定したグループだけ、`### v0.11.0 名前` のように見出しへ番号を付ける。
- グループが大きい場合は、`####` 見出しでさらに分割してよい。

## タスク

### v0.14.0 セッションのまとまりを軸にした検索・閲覧の再設計

取り込み・出力の検討案と未確定点は [v0.14.0 参考資料](v0.14.0-reference.md) にまとめる。複数のログ入力は会話の identity、旧 DB 移行、REF と検索条件を変えるため同じ v0.14.0 に含め、契約確定後、移行・検索より先に動く取り込み経路を実装する。全体を一度の v0.14.0 リリースとして扱い、見出しは作業段階を示す。以下は上から進めるコミット単位の未着手タスク。各実装タスクに対応する検証と、必要な正本・usage・README・skill の更新を含め、[必須 gate](../docs/rules/verification.md) を通す。互換性対応は今回の前提にしない。

#### 1. 契約と代表例の確定

- [ ] 元ログの不足調査と取り込み・出力契約を確定する

  Codex の親 ID と Claude Code の未走査の子ログを代表 fixture にし、孫の直接親、引き継いだ文脈、原文・順序・日時に追加の取り込み変更が必要かを source ごとに判定する。複数入力の設定・入力 path の正規化と移動時の扱い、入力で区切る会話 identity / REF と親子関係・取り込み状態、入力 path フィルタ、原文と発言番号、正規表現、一覧・詳細・原文の出力契約を確定する。専用 `migrate` の旧 DB・移行先の指定、元 DB の識別方法、根拠のある旧行の入力対応付けと所属不明の保持、初回コピーと Codex 部分置換の成功条件も決める。追加変更が必要なら後続の該当 source タスクへ含め、独立して大きい変更だけ取り込み段階に分ける。未知情報をどう残すかまで決まり、複数入力で同じ会話 ID を持つ代表 fixture と契約を記録して保存・検索実装へ着手できる状態を完了とする。

#### 2. 複数入力と親子ログの取り込み

- [ ] 複数入力の設定から共通 DB への取り込みを実装する

  設定で DB の保存先と `inputs` の名前・source 種別・ログのルートディレクトリを指定できるようにし、設定がない場合は現行の標準ルート・標準 DB を使い、明示した `--db` は設定の保存先より優先する。source 種別は adapter 選択、名前は表示に使い、DB へは保存しない。入力テーブルにルート path と source 種別を一度保存して短い内部 ID で会話を参照し、会話・発言・取り込み状態の識別を入力ごとに分ける。同じ会話 ID の異なる入力を混ぜず、同じ入力の差分再開・再処理を保つ。Claude Code / Codex の複数ルートと現行の単一入力、同名 ID、path の表記差を fixture で確認し、設定・CLI・保存・取得がつながる単位で完了する。

- [ ] 共通保存モデルと Codex の親子取り込みを実装する

  共通正規化型・SQLite schema・書き込みを Codex adapter と一緒に変更し、元ログの直接の親 ID を同じ入力内の関係として保存する。親が未取り込みでも手がかりを残し、親・子・孫の本文を独立して保持する。発言日時の欠落を開始時刻で補完せず、元の順序と未知日時を残す。新規 DB への保存、差分再開での metadata 復元、再処理の無重複、子先行・親後着、別入力の同名 ID を fixture で確認する。Claude Code の root と Cursor Agent も新規 DB への取り込み・原文取得が動くことを確認し、schema だけの先行コミットにしない。

- [ ] Claude Code の子・孫ログを独立した会話として取り込む

  subagents 配下の走査、同じ入力内の root と同じ session ID を持つ子の独立 identity、所属 root と根拠のある直接親、必要な metadata / tool call の読み取りを実装する。兄弟・孫の本文を root に混ぜず、親が不明でも子を単独で残す。差分取り込み・再処理・親の後着・別入力の同名 ID で本文の重複や所属の変化を誤らないことを確認する。

#### 3. 既存履歴の移行

- [ ] 専用 `migrate` で既存履歴を移し、残存ログのある Codex セッションだけ置換する

  専用 `migrate` で既知の旧 DB の本文・既知 metadata を別の新 schema DB へ移し、残存 rollout を最新の正本として同じ入力・session ID の Codex 会話を丸ごと置換する。旧行の入力所属は信頼できる根拠がある場合だけ対応付け、不明なら未知のまま保持して、別入力の同名 ID だけを根拠に旧行を置換しない。同じ ID の複数 rollout も同じ入力内で組にする。初回コピー、schema revision、移行元の識別と初回コピー完了の記録を一つのトランザクションで確定する。再実行先は同じ移行元からの初回コピー完了を証明できる DB に限り、通常の新規 DB や別の移行元から作った DB は拒否する。旧行削除・全文保存・取り込み状態更新はセッション単位のトランザクションにし、再実行では初回コピーを繰り返さず、残存ログの全 ID を再び置換する。ログのない履歴、失敗した対象、Claude Code / Cursor Agent の保存済み履歴を保持する。親不明、複数 rollout、未解析行、初回コピー中断と再開、途中失敗、path 変更、再実行、ログ後着後の再実行、無関係な移行先の拒否、入力別の同名 ID と所属不明の旧行を fixture で確認する。通常の `import` は差分取り込みを続け、`search` / `show` は非対応 DB の移行を案内する。別 DB への移行と切り替えを案内し、[ADR 0019](../docs/decisions/0019-remove-legacy-backfill.md) の再検討結果を実装時の正本と新しい判断記録へ反映する。

#### 4. 会話の参照と原文取得

- [ ] REF とセッションのまとまりを共通に解決する

  保存した関係から root・子孫・独立した会話を入力内で解決し、検索と原文取得で共有する。入力間・source 間の同名 ID、Claude Code の同一 session ID の兄弟、親欠落・親後着、直接親不明を区別する。発言番号と会話内の順序も共通化し、REF から入力を含む元の会話へ戻れることを確認する。

- [ ] `show` を会話の REF と原文に対応させる

  単一 REF の本人全文、子だけの参照、子孫を会話別に含める指定と JSON 出力を実装する。新しい取り込みの本文と発言番号をそのまま取得でき、日時や親が不明な会話も表示できることを確認する。

- [ ] `show` に発言選択と複数会話の一括取得を加える

  先頭・末尾 N 件、発言番号範囲、指定日の実発言、複数 REF を扱う。日時条件と dayBoundary の共通処理を整え、日付だけの上限・日時上限・未知日時を確認する。REF と子孫指定の重複・出力順を固定し、Daily Note 用の原文を一括取得できることを確認する。

#### 5. セッションのまとまりを軸にした検索

- [ ] 共通照合器とセッション内の全一致検索を実装する

  正規表現・複数 `-e`・`-F`・まとまりの AND を共通照合器で扱い、`search --session REF` につなぐ。全一致の位置・前後の原文・会話の REF・発言番号・箇所番号、明示した場合だけのページ化を返す。同一発言内の複数一致、無効式・空一致、親子をまたぐ AND、`show` との原文・番号の一致を確認する。

- [ ] `search` をまとまりの一覧と総数・ページ化へ切り替える

  語の省略、project / alias、入力 path、source に対応し、入力条件で候補を絞ってから同じ照合器で本文を判定し、まとまりへ集約する。TSV・JSON に本文抜粋を混ぜず、総数・今回の件数・limit / offset・続きと次位置を返す。SQL の照合登録をつなぎ、一覧と詳細の同一判定、AND、入力別の同名 ID、0件・末尾超過、ページ化前の総数と一度の検索内の整合性を確認する。実データで照合時間を測り、入力テーブル参照を含む一覧・検索の時間を確認する。

- [ ] 一覧に活動日と取り込み日時の絞り込みを加える

  共通の日時処理を使い、`active` / `started` / `last` / `overlap`、期間、dayBoundary、`--imported-since` を実装する。各条件の本文照合範囲、親子の日時差、未知日時、日付上限、AND との併用、filter 後の総数を確認する。最後の記録を完了時刻として扱わない。

#### 6. CLI の統合と通しの確認

- [ ] 一覧検索と原文取得へ CLI の入口を統合する

  完成した `search` 一覧へ `sessions` を統合し、期間だけで複数全文を出す入口を一覧 → 複数 REF の `show` へ移す。usage・案内・skill に、検索 JSON から必要な REF を選び、重複を除いて一回のシェル呼び出しで `show REF...` に渡す例を揃える。一括取得能力が保たれることを確認する。専用の一括コマンドは増やさず、各機能の文書同期は先行コミットで済ませ、このタスクは入口統合の差分に限る。

- [ ] 二つの利用場面を取り込みから原文取得まで通して確認する

  各コミットの検証に加え、複数入力を含む代表 fixture の新規取り込みから、単語検索 → 一覧 → 全一致 → 原文と、指定日の一覧 → 複数会話の実発言取得を通す。入力・source ごとの親子・孫、同名 ID、未知日時・親欠落、REF・発言番号・JSON の整合性を確認し、v0.14.0 のタスクと参考資料を整理する。
